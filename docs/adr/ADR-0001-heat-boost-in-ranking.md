# ADR-0001：热度参与检索排序

- 状态：已采纳（追认）
- 日期：2026-11-24
- 版本：1.8.0 起生效，1.9.0 补记

## 背景
1.8.0 在 `query.py` 的衰减因子之上加了热度放大，用召回次数、被标有用次数、最近召回时间、间隔复习时间计算。上线时没有留决策记录，1.9.0 验收第 10 项要求对齐。

## 决定
保留现状：热度参与排序，不改成 shadow。

- 公式：`heat = 1 + min(0.8, usage + recency + spacing)`，最多放大 **1.8 倍**。
  - usage：`0.25·(1−2^(−recall/8)) + 0.20·(1−2^(−useful/4))`
  - recency：`0.20·2^(−距上次召回天数/14)`
  - spacing：`0.15·min(1, 距上次间隔复习天数/30)`
- 没有使用信号的旧记录系数为 1.0，不受影响。
- 只放大，不压低；衰减和 valid_to 过期降权照旧先算。

## 理由
- 已在生产跑了一周，收尾版本不改行为。
- 有上限（1.8 倍），影响范围可预期；但它对低相关、高频事实的抬升程度没有测过，见下方待办。

## 开关与回滚
- 关闭：在 `mimir.service` 环境里设 `MIMIR_HEAT_BOOST=0`，重启 API 生效。关闭后系数只剩衰减和过期降权，不再乘热度。
- 回滚不需要数据迁移：开关只影响排序计算，召回计数等信号照常记录。

## 已知不足（1.9.1 待办）
- **没有评估数据**证明热度改善了排序质量。1.9.1 用基准集做开/关对比（召回@k、MRR），结论回写本 ADR。
- 热门事实可能形成"越召回越靠前"的正反馈，评估时一并看。
