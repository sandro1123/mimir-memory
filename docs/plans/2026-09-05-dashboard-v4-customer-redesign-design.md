# Dashboard v4 设计稿：以普通客户视角重构信息架构（13 tab → 客户导向）

**日期**：2026-09-05
**状态**：用户已批方案 A（三屏极简）
**设计输入（用户六问裁定，逐字保留）**：
1. 主场景 = **记忆管家（个人用户）**——日常看「我的助手今天学了什么/记住了什么」，核心动作=审批+纠正
2. 开发面 6 tab = **收进隐藏抽屉**——客户视图干净，开发数据不丢
3. 首页 = **「今日记忆」时间线**——像刷动态：今天/昨天/本周，待审嵌在流里顺手批
4. 检索 = **融入首页**——「问我的助手」搜索框常驻顶部，顺手批结果里的错误条目
5. 记忆呈现 = **卡片信息重写**——生活语言（学到什么/从哪学/有多确定），技术词全藏
6. 健康 = **一盏健康灯**——绿=正常，黄/红=点开看详情，不要运维指标墙

## 一、问题陈述

现 13 tab 是 v11~v14 API 面原样铺开的开发者控制台：总览/管线/记忆/审批/来源/活动/意见/技能/检索/系统/符号/代码/联邦。其中 6 tab 纯开发面（管线/技能/系统/符号/代码/联邦），唯一客户（用户本人）日常用不到；客户高频动作（看今天学到的、审批、纠正、查记忆）被稀释在导航里。用户原话：「很多目前的功能，我好像都用不到啊」。

## 二、方案 A 结构（已批）

### 2.1 导航骨架：底部 3 tab + 开发者模式开关

```
┌────────────────────────────────────────┐
│  ● 我的记忆管家          [🔍 问我的助手] │ ← 健康灯 + 常驻搜索（全局）
├────────────────────────────────────────┤
│  今天 · 9月5日                          │
│  ┌ 📖 今天学到 3 条 ────────────────┐   │
│  │ 卡片：学到什么/从哪学的/有多确定   │   │
│  ├ 💬 2 条等你确认（内嵌审批卡）────┤   │
│  │   [✓ 是这样] [✗ 纠正它]          │   │
│  ├ 🗑 已淡忘 1 条 ─────────────────┤   │
│  └─────────────────────────────────┘   │
│  昨天 · 9月4日（折叠）                    │
│  本周更早（折叠）                        │
├────────────────────────────────────────┤
│  🏠今天    📖记忆库    ⚙️设置            │ ← 底部 3 tab
└────────────────────────────────────────┘
```

- **今天 tab**：时间线首页（学习事件流+待审内嵌+淡忘通知）
- **记忆库 tab**：全部记忆卡片流+筛选（时间/来源/「有分歧的」）+待审角标
- **设置 tab**：学习源管理（「我的助手在哪学习」）+ 清理策略 + **开发者模式开关**

### 2.2 开发者模式（旧 13 tab 的归宿）

设置 →「开发者模式」开关。关闭=默认客户视图（3 tab）；打开=旧 13 tab 全量导航恢复（物理保留全部代码，nav 数组双套渲染）。零功能丢失，无回退风险。

### 2.3 归属重排明细

### 2.4 健康灯逻辑

- **绿**：API 200 + dead_letters=0 + 四 projector 无错 + 待审数 < 阈值（温和提醒级）
- **黄**：非致命异常——单个 projector lag/dead_letters>0/待审堆积
- **红**：API 不可达或 /ready 失败
- 点灯 → 运维详情浮层（含 v14.1.0 P1 诚实遥测 degraded 指标，两件天然合流）
- 数据源：`/v14/ready`（现成）+ 既有 /api 各端点聚合

### 2.5 卡片信息重写（客户语言映射）

| 技术字段 | 客户语言 |
|---|---|
| fact + domain | 「学到：{内容摘要}」 |
| source/origin | 「从哪学的：{来源名}」 |
| confidence 0.87 | 「确定程度：很确定 / 还行 / 待观察」三档 |
| review_required | 「等你确认」+ [✓是这样] [✗纠正它] |
| decay_tier L4 | 「已淡忘」+「还要它吗？」 |
| disputed | 「有分歧的记忆」（记忆库筛选视图） |

三档置信映射：≥0.8 很确定 / 0.5~0.8 还行 / <0.5 待观察。

## 三、技术设计

### 3.1 架构（沿用现栈，零新依赖）

- 前端：Alpine.js 单文件 index.html（不引框架；沿用现有 navItems 模式，增 `devMode` 双套渲染）
- 后端：dashboard/main.py 增 3 个聚合端点（把每屏多端点拉取合并为单请求）：
  - `GET /dashboard/today` — 时间线（学习事件+待审+淡忘，按日分组）
  - `GET /dashboard/library` — 记忆库（分页卡片流+筛选参数）
  - `GET /dashboard/health-light` — 灯色（聚合 /ready + projector + dead_letters + 待审数）
- 旧 13 tab 端点全保留不动（开发模式直接复用）

### 3.2 后端数据拼装

- `today`：`/v14/events`（学习事件）+ `/v14/facts?review_required`（待审）+ decay events（淡忘）按 created_at 分日
- `library`：`/v14/facts` 分页 + domain/source 筛选 + disputed 过滤
- `health-light`：`/v14/ready` + overview 现有字段聚合（复用 dashboard 现有对 Mímir API 的调用封装）

### 3.3 审批动作接线

时间线/记忆库的 [✓][✗] 按钮直接调用现有审批 API（现审批 tab 同款端点，仅换皮）。✗ 打开纠正输入框（写回 update + 记入 disputed/反馈流）。

### 3.4 错误处理

- 3 个聚合端点内任一上游失败 → 端点降级返回 partial + `degraded: true`（前端灯转黄）
- 前端 fetch 失败 → 卡片区显示「暂时连不上我的记忆管家」+ 重试按钮（不白屏）
- 客户视图所有空态：明确文案（如今天没学到新东西=「今天还没有新记忆，去和你的助手聊聊吧」）

### 3.5 兼容与回退

- 开发者模式默认 **off**（localStorage 记忆选择）
- 部署 = scp frontend/index.html + backend/main.py 到部署树 + systemd restart（沿用 v3 部署配方，manage.sh 不动）
- 回退 = 还原两文件 + restart（部署树留 .bak-* 备印，同现有约定）
- repo 与部署树同步 commit（同 v3 流程）

### 3.6 测试

- 后端：3 个聚合端点各加 pytest（正常/partial 降级/空态三态）——放 dashboard 现有测试目录
- 前端：冒烟=全 tab 可达性（现有 switchTab 回归思路）+ 客户视图三屏走查
- 验收（客户语言标准）：打开 10 秒内明白「今天学到什么」；看+批全程不离开首屏；开发模式全功能可达

## 四、不做清单（YAGNI）

- 不做账户/多用户/权限（单人系统）
- 不做对话式浏览（用户已裁卡片式）
- 不重构后端 API（只加聚合层，旧端点不动）
- 不引前端框架/构建链（Alpine 单文件保留）
- 不动 CSS 设计系统大调（沿用现有 token，仅新增卡片样式）
- 「意见」不做独立投影页（并入记忆库筛选）

## 五、实施顺序（writing-plans 输入）

1. 后端 3 聚合端点（TDD：正常/partial/空态）
2. 前端健康灯+搜索框（全局头）
3. 今天 tab 时间线（含审批内嵌）
4. 记忆库 tab（卡片重写+筛选+待审角标）
5. 设置 tab（学习源+开发者模式开关）
6. 开发者抽屉（13 tab 恢复渲染）+ 空态文案
7. 部署树同步 + systemd restart + 冒烟验收
8. repo commit + CHANGELOG（dashboard v4.0.0）
