## 1.4.0 可读性（规划中）
> **内核**：护城河（ACL/账本/谱系/诚实遥测）目前只对**人类**可见——
> 1.3.0 建了 Dashboard 那半边，没建 **agent 消费的半边**。缺口三件事：
> 召回为什么命中、以什么代价命中、超预算时到底丢了什么。
> claude-mem 的三段式渐进披露 + 上下文预算给了反例模板，但它的失败模式
> （超预算时静默把整块换成 ~2KB stub 却仍报 success，见其 #3802/#1899）
> 是 Mímir 必须**反对着抄**的那半。

12. **召回解释的机器可读面**：`/v8/query?trace=true` 已产出人读漏斗
    （六阶段 found|not_found|degraded 判语）；1.4.0 交一份**定版、带
    版本号、按声明预算封顶**的 `recall_explanation` 对象——逐条 fact
    带来源层/锚/通道/排序理由，供 agent 程序化消费，不再靠人读日志反推。
13. **三段式渐进披露**：索引（~50-100 token/条）→ 时间线/上下文 →
    仅对选中 ID 展开全文（~500-1000 token/条）；**游标由服务端持有
    不下发**，跨步拒绝任意 ID / 改范围 / 过期 token。让 agent 花自己
    的上下文花得明白，而不是一次拉全表再自己砍。
14. **预算诚实**：超预算时**禁止**整块静默替换成 stub 还报 success——
    显式回 `budget_exceeded` + 丢弃清单 + 收窄建议。凡「宣称成功但
    载荷被换掉」的形态一律不允许出厂。
15. **控制台 v2 余项**（承接 1.3.0 顺延）：联邦 tab · 实体图可视化 ·
    谱系链浏览器——把 1.4.0 同一套解释对象渲染给人看，人机共用一份真相。

## 1.5.0 信任度（规划中）
> **内核**：判重的自动化边界裁决落地。判词只有一句：
> **ADD 全自动；UPDATE/DELETE 永不自动。人工是升级路径，不是运行模式。**
> 裁它的依据不是设计美学，是实测——「人工模式」在生产中等同于永远排队，
> Mímir 自己的 human_review 队列 6 件积压（含 `21109d6b` 带内网元数据
> 地址）就是这句话的成本账单。所以自动化要按**动作可逆性**切，不按
> 「谁来决定」切：mem0 按前者切（全 LLM + 只准 ADD）因而能全自动，
> 按后者切的系统必然退化回人工瓶颈。

16. **判重三档信任分层**：Tier-0 确定性静默合并（content_hash /
    规范化标题键，无 LLM）；Tier-1 LLM 辅助但**只准 ADD**；Tier-2
    判断类**永不自动执行** → 进 pending 队列等人工。冷启动门
    `isFuzzyReady(db, project, minDocs)`——样本不足时不启动模糊判重。
17. **ADD-only 写入闸**：把「UPDATE/DELETE 不由 agent 自动触发」做成
    **物理不变量**入写入路径（沿用列级物理不变量的既有实践）；先上
    「只告警不拦」形态观察，验证无噪声后再收紧为拦阻。
18. **递归精炼**（自 1.4.0 移入）：后台把相关多条碎记忆递归合并为
    高层抽象，对抗记忆熵增；产物 **soft-superseded（不物理删除）**
    + 一键回滚 + **LLM 只建议不 commit**。与 retention 衰减互补，
    与 Tier-2 判重共用同一条升级路径。
19. **pending 队列治理面**：human_review 从死信箱升为一等治理界面——
    现存积压清仓 + 队列操作 API + 停留时长可观测（对应 1.3.0
    「last_seen 停滞族」的同类病灶：建了没人调）。
20. **Reflect 启用判定门**：`MIMIR_REFLECT_ENABLED=0` 且 `reflect_runs`
    表尚未建；观察期满后由用户决定是否转正。转正则先补表、补可观测性、
    补 ≤6 LLM/轮与 6h 一轮的节律留痕，再谈默认值。
21. **任务交接协议**（承接 1.3.0 顺延）：POST /v12/handoff 任务上下文包
    （目标/已试路径/开放问题/相关事实引用）→ MEX 子格式；**必须带谱系**，
    否则交接即断链。

## 2.0.0 双时态（方向题，立而不排）
28. **双时态 schema + 查询语义**：valid_time（事实**何时为真**）与
    transaction_time（我们**何时知道**）分开存，使「当时为真」与
    「当时已知」都成为可回答问题。Chronos + valid_from/until 已是半边
    底子；这是把 Zep 的时态实体图补成 Mímir 自己的双时态。
29. **强不可抵赖谱系**：签名 / WORM 存储，从 1.1.0 的 tamper-evident
    升到 non-repudiation。aduMEI 同思路；措辞分级沿用其诚实披露，
    不宣称做不到的强度。
