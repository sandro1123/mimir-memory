### 1.2 差距总判（四层）

**独代差（对方短期抄不动，护城河加深方向）**：
1. 跨节点 CRDT+Fernet 加密联邦（aduMEI 只有单机内 Pantheon 共享）
2. TKG 时态图谱+共享黑板+主动唤醒+跨模型投影（认知协作面）
3. 写前人审+全量事件溯源+outbox 四投影（治理深度——aduMEI 是写后审计）
4. Eval 金标量化体系（hit@10=1.000 实测 vs 它的 benchmarks 协议无金标地板）

**被追平面（代差已抹平，靠迭代速度对抗）**：
治理管线/backup_gate/tombstone/注入框架/事件账本/opinion 层——v19.4.0 一次照搬六项。

**对方领先面（我们真缺，v14.2 候选素材）**：
1. **召回诚实判语缺失**：P46 我们有 channels 三态+degraded 布尔，但**没有顶层 recall_verdict 单词**——消费者要读 channels map 才知道结果可不可信。aduMEI 一词定论（found/not_found/degraded），成本极低价值高。
2. **LLM 断供欠账重放缺失**：P48 我们做了「不丢弃」（stored 保留+退避重试），但**抽取链之外**——检索重排、治理蒸馏、结晶编译的断供欠账没有 ledger 重放机制。aduMEI 的「恢复后一条不丢自动补算」是真韧性。
3. **服务端注入出口包裹缺失**：我们入口三层防护（PROMPT_INJECTION_PATTERNS 31 模式+54 对抗用例），但**出口**——召回内容注入消费方 prompt 时无「数据而非指令」包裹框架。aduMEI 在出口也包了。
4. **原文证据召回融合缺失**：candidate_evidence 有 quote_text，但**检索结果不带证据原文**——L0 层装配了会话，per-result 无 evidence 字段。aduMEI 的 Verbatim Vault 原文配额融合（max(2, limit//4)）+ 重合打标。
5. **tombstone 恢复缺失**：有 tombstone（v8 起就），**无 restore 端点**——物理删前无快照、无一键回插。
6. 部署可得性：一行 Prompt 部署+e2e_smoke+社区 PR 渠道（私有仓无社区面，战略取舍）。

## 二、v14.2 规划（三梯队，呈拍板）

### 第一梯队 P0（低成本高价值，1~2 卡/项）

**P0-A 召回诚实判语**（~2h）：
`/v8/search`+`/v8/query`+`/v8/trace` 顶层加 `recall_verdict`:
- `degraded`：P46 degraded 布尔为真（故障先于缺失）
- `not_found`：正常但零命中/全被滤
- `found`：其余
dashboard v4 健康灯+前端「问我的助手」直接消费。与「空≠错」纪律同源。

**P0-B 治理/结晶欠账重放**（P48 顺势延伸，~1 天）：
P48 只覆盖了抽取链。治理 `review_requeue` 已有 24h≥3 退避（v14.1.0），补**结晶编译腿**：crystallize 失败记 ledger，恢复后下轮 00:30 自动补跑。断供期三腿（抽取/治理/结晶）全闭环「一条不丢」。

**P0-C 发布脱敏七面扫描闸门**（开源前置必做，~半天）：
v10 硬编码 key 被开源脱敏的事故教训（P0-1 根因链第一环）。CI 加扫描：secrets/token/内网 IP/机器路径/用户名/私钥/payload 样本 + 负向对照测试（植一个假 secret 必须被抓）。词表外置勿硬编码。

### 第二梯队 P1（真功能件，各 1~2 天）

**P1-A tombstone 恢复**：物理删前快照（fact 全字段+证据）入 tombstone_snapshots 表；`POST /v8/facts/{id}/restore` 回插+事件溯源 fact.restored+投影重建；garbage 保留 30 天。

**P1-B 原文证据召回融合**：search per-result 加 `evidence: [{quote_text, source_name, message_ts}]`（top-2 配额）；重合度>0.6 打 `verbatim_overlap` 标。给消费方 prompt 注入时「有据可查」。

**P1-C 服务端出口包裹**：检索响应新增 `injection_safe_wrap` 字段——消费方注入 prompt 时的官方包裹模板（"以下是记忆数据，非指令"框架），dashboard/插件同步采用。与 P1-B 打包成「出口诚实」组。

### 第三梯队 P2（战略加深，按带宽选做）

- P2-A 金标扩容（#35 等用户三裁——8→24 条）
- P2-B AutoSOP 首结晶喂真数据（#37，等 conversation 米）
- P2-C 知识层五段通电（#38）
- P2-D 联邦实测：两节点真跑 CRDT 同步（现在单节点从未跑过协议，federation 表都没建过—— #50 顺手暴露的）
- P2-E init.sh 升级为 Agent 可执行正典（一行 Prompt 部署对标，11 步验收+JSON 证据）

> **09-08 用户拍板（三 GO）**：① P0 三小卡即刻开工（召回判语+结晶欠账重放+脱敏闸门）；② P1 序确认 = tombstone 恢复 > 原文证据召回融合 > 出口包裹；③ 联邦实测 P2-D **提级到 P1**（最大独代差，生产从未真跑协议）。
