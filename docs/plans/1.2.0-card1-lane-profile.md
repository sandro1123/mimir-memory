# 卡一 SPEC：引擎挡位一等化（LaneProfile）· Mímir 1.2.0

状态：待施工 · 基线 commit `34bbd5b`（1.1.0 已上线生产后第一个 commit）

## 一、病机（不是需求，是查出来的）

B-002 首跑 LoCoMo（`docs/RESULTS.md`）暴露一个结构性隐患：

1. **通道开关是隐式算出来的**。`QueryKernel.search` 里
   `if request.use_vector and self.vector is not None and self.embedder is not None`
   ——「这条道通不通」由 *请求字段 × 接线状态* 三者隐式决定，没有一个对象回答
   「此刻我到底有哪些车道」。
2. **报告里那句 `external: "fts-only trigram + RRF (no vector lane)"` 是人手写的散文**
   （`scripts/run_benchmarks.py` 的 `report["engine"]` 字典）。它和引擎行为**没有任何绑定**：
   一旦给基准腿接上向量道，报告会继续写「no vector lane」——数字对、描述错，且**永远不会有人发现**。

这两条合起来就是本卡要切的东西：**挡位必须是引擎自己算出来、自己序列化的一等对象**，
而不是人的散文。散文会撒谎，算法的输出不会。

## 二、契约设计

### `LaneProfile`（`mimir_v8/query.py`，frozen dataclass）

```python
@dataclass(frozen=True)
class LaneProfile:
    active: tuple[str, ...]      # 本次实际参与候选池的车道（排序恒定）
    disabled: tuple[str, ...]    # 被请求字段关掉的
    unavailable: tuple[str, ...] # 请求要但接线没有（依赖缺失/未注入）
    degraded: tuple[str, ...]    # 开着但本轮断路器降级（closed/degraded/open）
    weights: tuple[tuple[str, float], ...]  # 该次生效的 RRF 权重，排序后

    def describe(self) -> str: ...   # 给人看的一行，进 report.engine
```

**推导唯一入口**：`QueryKernel.lane_profile(request) -> LaneProfile`。
- `active` / `disabled` / `unavailable` 三分是**穷尽且互斥**的，恒有
  `len(active)+len(disabled)+len(unavailable) == len(ALL_LANES)`。
  加新车道时这个恒等式必须仍成立，否则有车道被静默漏掉。
- `anchor` 不是相似度车道（直查 canonical，不走断路器），不进这个三分，
  但在 `describe()` 里单独说明——它与 `CHANNEL_WEIGHTS` 的四键关系写死在测试里。

### 三处必须改成「从挡位派生」

| 位置 | 现状 | 改后 |
|---|---|---|
| `run_benchmarks.py` `report["engine"]["external"]` | 手写散文 | `kernel.lane_profile(req).describe()` |
| `run_benchmarks.py` 同段 | 无 | 新增 `external_lanes: list[str]`（机器可读，供下游对拍） |
| `QueryKernel.search` 的 `channels` 段 | 各分支各自写 `channel_states[...]` | 仍保留（那是**运行态**，含断路器降级），但补 `lane_profile` 字段 |

## 三、`--vector` 开关（基准腿接向量道）

- 离线加载 bge-m3（`HF_HUB_OFFLINE=1` + `local_files_only=True`），
  chroma `PersistentClient` 落 `TemporaryDirectory`——**绝不灌生产库，绝不复用生产 collection**。
  设备实测：加载 4.5s、1024 维、0.469 s/条、272 条 ≈ 128s。
- **负向钉（这是本卡的硬门禁）**：模型不可用时**不得静默退回 fts-only 出数**。
  语义是 `--vector` 说了要向量道，给不了就**非零退出**，
  理由和 `--limit` 那条一样：悄悄换挡位 = 报告里的描述与数字来自两套引擎。
  反之（默认不开 `--vector`）走 fts-only，并在 engine 段如实写出来。

## 四、TDD 三钉

**正向**
1. 注入 vector+fts+graph 三道、`use_*` 全 True → `active` 三道齐全，
   `disabled`/`unavailable` 空，`describe()` 含三道名。
2. `report["engine"]["external"]` 与同一次运行的 `lane_profile.describe()` 逐字相等
   （钉住「描述不得与人写的散文脱节」）。
3. `--vector` 跑通，`external_lanes` 含 `"vector"`。

**边界**
4. 请求关掉 fts → fts 进 `disabled`；未注入 graph → graph 进 `unavailable`；
   恒等式 `active+disabled+unavailable == 4`（三相似度道 + anchor）仍成立。
5. `--vector` 且 `--limit` 超顶 → 仍按老规矩入口报错（两门禁不互相吞）。
6. `weights` 输出按名排序，跨次运行可比。

**反向（本卡的核心守卫）**
7. 模型缺失 → `--vector` 非零退出，**stderr 明写「已请求向量道但不可用」**；
   断言 stdout **不含**任何指标段（不许「看起来测过」的数字）。
8. 关掉三道相似度 → `active` 只剩 anchor，`describe()` 不谎称有语义车道。
9. 断路器降级某道 → `degraded` 含它且 `active` 仍含它（跑过 ≠ 降级 ≠ 关闭，三态不许塌成一态）。
