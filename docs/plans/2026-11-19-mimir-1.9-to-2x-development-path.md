## 1. 规划原则（不可妥协）

1. **治理基因不稀释**：自动捕获/反思/合并/精炼/回写的产物一律走候选→评审→入库；LLM 只建议不 commit；AGG 可自动，UPDATE/DELETE 不自动直写 canonical facts（除非显式翻案并留审计）。
2. **诚实判语不打折**：`recall_verdict`/通道状态/degraded 与漏斗逐步 verdict 对外一致；“没查到”≠“通道坏了”；预算/降级/缺能力必须可见。
3. **先量后写**：热度、衰减、精炼、时态加权等策略先量靶子与 baseline（可寻址样本/对照实测），再上线默认行为。
4. **Fail-closed**：账本写失败不删；无模型不伪造摘要；不确定宁可降级/暂存候选，不静默污染真相源。
5. **适配声明式、最小侵入**：Adapter 以 contract 驱动；不改 Mirasim/各宿主的模型路由与凭据；安装幂等、可回滚、可审计。
6. **可证伪验收**：每个里程碑绑定指标与反向钉（含“无回归”与“失败路径”），避免“看起来完成”。

## 2. Mirasim 适配总策略（贯穿 1.9.x）

Mirasim 是**托管多 Agent 的编排壳**（非单一 CLI），适配必须分层，避免把“壳能力”误当“Agent 原生能力”：

| 层级 | 目标 | 方式 | 1.9.x 归属 |
|---|---|---|---|
| **L1 MCP 基线** | “接得进来、能消费” | 生成/幂等合并 `~/.mirasim/mcp.json` 的 `servers[]` 条目（正确 `type/command|url/env/catalogId/enabled/agents`），不碰模型与凭据；支持备份+原子写 | 1.9.0 必做 |
| **L2 宿主 Hook 复用** | “自动预取+自动沉淀” | 对 Mirasim 托管的 Claude/Codex 探测并复用原生 hooks（`SessionStart`→bootstrap，`SessionEnd`→hooks/ingest）；标记 `host=mirasim` 与会话归因；不可用则降级 L1/显式 | 1.9.0 探测启用（可降级） |
| **L3 编排面桥接** | “定时/远程会话不失忆” | `schedules.json` 任务前后显式 bootstrap/ingest；MiraChannel/Goal 会话以显式/C 档兜底归因（`connector_id/owner_principal/session_id` 稳定） | 1.9.1（schedules 优先）→ 1.9.x 补齐 |
| **L4 体验增强** | “首轮即有上下文” | Server 侧预取或 Mirasim skill 只读预取（可选，依赖宿主/壳注入点） | 1.9.x/1.10 视可行性 |

**Mirasim Adapter Contract（草案要点）**：`name=mirasim`，`kind=hybrid`（mcp + hosted-hooks-detect + explicit），`mcp_inject.format=servers_array`，`identity.connector_prefix=mirasim`，`constraints={no_model_routing_change,no_credential_write,install_atomic_with_backup}`。实现须以 schema 校验并与安装器/端到端测试绑定。

## 4. 版本规划

### 4.1 1.9.x —「Connect & Capture」（接入、自动采集、诚实面基础）

**主题**：让主流宿主（含 Mirasim）低摩擦接入并自动沉淀为可治理记忆；先把“采得到、分得清、看得诚实”做实。

#### 1.9.0（里程碑）
- **Adapter Contract v1**：`mimir_v8/adapters/` + `contract.yaml`/schema 校验；声明 `kind(hook|mcp|explicit|hybrid)`、capture/bootstrap/ingest、identity、constraints。
- **Mirasim 适配 L1+L2**：`mirasim.yaml`；安装器对 `mcp.json` servers 数组幂等合并+备份回滚；托管 Claude/Codex hooks 探测启用与降级；`agents` 作用域可配。
- **自动捕获基线（承接路线图 1.8 核心）**：A 档 `SessionStart/End` 接入、B 档 MCP 显式触发、C 档 HTTP/显式兜底；统一走 `ConversationEnvelope`/STM→候选结晶（不直写 facts）。
- **热度 v1（可观测、低风险）**：`search_feedback` 从“只写”补齐“读”接线的最小闭环；区分检索曝光与确认使用（fusion/recall 计数口径先定稿并落库/迁移，默认行为保守）；账本先行删除钉。
- **召回诚实面契约**：对外暴露/统一 `recall_verdict` 与 trace/funnel 数据结构（API/MCP 可消费字段定稿），确保 degraded≠empty；具体 UI 漏斗可后置但契约先行。
- **Thor/Odin 自动采集纳入**：建立稳定 `connector_id/owner_principal` 与可摄入来源，接入 CDC 或 SessionEnd ingest，纳入可观测告警（同 1.8 落地补充要求）。
- **验收（示例）**：
  - Mirasim：L1 安装幂等、三类托管 Agent 可调 MCP；Claude/Codex 会话在可用时自动 bootstrap+产出候选，不可用时正确降级。
  - 自动捕获：按 A/B/C 分档统计触发覆盖率/误捕获率/候选转正率；重复会话幂等。
  - 诚实性：通道故障注入下 verdict=degraded 且不伪装 found；删除路径账本失败不删（反向钉）。
  - 对照：输出/更新 `docs/BENCHMARK-COMPARE.md` 初版。

#### 1.9.1（硬化与桥接）
- **Mirasim L3（schedules 优先）**：定时任务前后 bootstrap/ingest 与归因；任务失败不阻塞主调度（可观测）。
- **适配器扩展**：OpenCode、DeepSeek（explicit/MCP 档）最小可用 + 安装文档/生成器。
- **热度 v1.1**：在实测基线支持下启用 spacing/活跃日因子的保守参数（默认可回退）；补回填迁移策略说明。

#### 1.9.x（维护线）
- 兼容性修复、安装器鲁棒性、hook payload 演进、观测与指标校准；不引入破坏性 schema 语义变更（除非单列 additive 且有迁移/回退）。

**1.9.x 非目标**：不做知识池复杂推理、不做双时态语义切换、不做“候选直写 canonical”。

### 4.2 1.10.x —「Consume & Recover」（知识消费、韧性与产品化收口）

**主题**：把 1.9 接入的记忆/知识“用起来、靠得住、可恢复”，补齐对 aiduMEI 等产品在可观测与韧性体验上的关键差距。

#### 1.10.0（里程碑）
- **知识消费面（承接路线图 §12.5）**：`mimir_entity_get` / `mimir_entity_search` / `mimir_runbook_get`（及对应 REST 对齐）；双池路由确定性规则与 `pool` 标注、预算独立统计；实体层 supersession 消费；Runbook 执行回写与 `battle_tested` 标记（与既有晋升判据对齐）。
- **召回可观测产品化**：漏斗/trace 在查询与运维面可视（在不破坏后端契约前提下，优先复用现有 API/聚合端点）；每步 verdict 完整。
- **韧性与恢复**：
  - LLM 断供/降级的欠账与补偿重放机制（可审计、幂等、可限流）；
  - tombstone 可恢复遗忘的用户/运维闭环（快照、恢复、索引重建一致性校验）；
  - 原文证据融合进召回（配额、去重/重合标记、主干优先），与治理/敏感策略兼容。
- **Mirasim L3 完整化**：MiraChannel/远程会话与 Goal/工作台关键生命周期的显式归因与摄入（在可探测事件范围内），实现“换入口不换脑”的可验收覆盖。
- **适配器广覆盖**：Cursor/Zed/主流 MCP 客户端配置生成与回归；DeepSeek/OpenCode 路径文档化与端到端样例。
- **验收（示例）**：知识工具注册+dispatch+语义钉；同查询双池命中时来源与预算可区分；断供恢复后欠账可重放且不重复副作用；tombstone 恢复逐位/一致性可验证。

#### 1.10.x（质量与效率线）
- **Lean/部署效率**（吸纳 aiduMEI 强项，分场景）：FTS-only/轻量挡位评估与可选交付、资源画像与启动自检（report 可机读）；发布脱敏/安全闸门与 CI 钉增强。
- **Dashboard 收口（可选切片）**：若未单列大版本，按“契约不变、vendor 本地化、strangler 拆分”渐进推进（与路线图 Dashboard v5 目标对齐，但避免绑后端破坏性变更）。

**1.10.x 非目标**：不引入 2.0 级别的全局时态语义重写；不做多跳图推理引擎。

### 4.3 2.x.x — 迭代演进（语义统一与能力深化）

> 2.x 采用**小步可回退**迭代：每个 2.x.0 只引入一类核心语义变化，配套迁移、兼容层与观测窗口。

#### 2.0.x —「Temporal Convergence」（时态收敛与谱系统一）
- **目标**：统一“何时发生/何时有效/何时记录/何时取代”的查询与存储语义，为知识与记忆提供一致时间观。
- **范围**：
  - 双时态模型落地（`valid_time` / `transaction_time` 或与既有 `valid_from/to`、`occurred_at` 的收敛方案）与查询谓词；
  - 谱系单一真相源收敛（`fact_supersessions` 与 relations/实体取代表达归一，视图兼容）；
  - additive 迁移、旧数据回填策略（可空/可降级）、只读兼容窗口。
- **前置**：1.9/1.10 的靶子度量、热度与检索链路稳定；时态语义设计稿评审通过。
- **验收**：时态查询可解释且可回放；历史样本在新旧语义下差异可量化；迁移可回滚。

#### 2.1.x —「Unified Brain Bridge」（记忆×知识统一检索与解释）
- **目标**：在 2.0 时态基础上统一 Memory/Knowledge 的检索编排与解释面。
- **范围**：跨池查询计划与证据归因（来源池、时间有效性、取代链）、Runbook/实体与事实的可追溯引用、Agent 侧“为何召回/为何未召回”的可解释输出增强。
- **验收**：典型“事实+规程+实体”任务可一次获得带来源与时态的结构化证据；诚实判语覆盖跨池路径。

#### 2.2.x —「Scale, Federation & Lean」（规模化与分发形态）
- **目标**：在不破坏可信底座的前提下降低接入与运行成本，强化多节点协作。
- **范围**：lean/嵌入式可选形态固化、跨节点联邦与权限/同步体验打磨（保持 CRDT/加密/ACL 优势）、大库下索引与保留策略优化、运维自检与容量治理。
- **验收**：资源档位可选且行为可预期；联邦冲突/权限场景有回归钉；升级路径平滑。

#### 2.3.x+ —「Cognitive Layer, Governed」（受治理的认知增强，按证据启用）
- **目标**：在前述基础稳定后，引入更高阶认知能力，但严格受治理与度量约束。
- **候选范围**（需逐项立项、先量后做）：Reflect 主动反思入库、写入时自编辑/语义判重、后台递归精炼/压缩（soft-superseded + 回滚）、画像/偏好蒸馏自动更新。
- **闸门**：每项必须有靶子量化、dry-run/灰度、误伤与回滚指标、与治理管线集成证明；未达闸门不进入默认开启。

## 5. 横切工作流（全版本）

- **对标与度量**：维护 `BENCHMARK-COMPARE.md`；关键策略（热度/时态/压缩）绑定 baseline 与回放报告。
- **Adapter 生态**：contract schema 版本化；安装器幂等测试矩阵（Mirasim/Claude/Codex/OpenCode/DeepSeek/Cursor/Zed 按档）。
- **安全与治理**：出口/注入防护、脱敏与 egress 策略与发布闸门持续演进；配置与密钥不入库/不外泄。
- **可观测性**：按 adapter 档与来源（含 Thor/Odin/Mirasim schedules）统计摄入、候选、召回 verdict、降级与重放。
- **文档与迁移**：每个 x.y.0 提供升级说明、schema/contract 变更、回退步骤与已知限制。
