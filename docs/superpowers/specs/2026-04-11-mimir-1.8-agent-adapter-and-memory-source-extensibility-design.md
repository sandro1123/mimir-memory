# Mímir 1.8.0 Agent Adapter & Memory Source Extensibility Design

> **Status:** Design finalized (approved in-session 2026-04-11) — implementation pending  
> **Date:** 2026-04-11  
> **Baseline branch:** `feat/1.8.0` @ `6cacd56` (`~/mimir-1.8.0-dev`)  
> **Scope:** 1.8.0 extensibility groundwork for (1) future agent integration paths and (2) future memory sources/connectors, without changing existing `/api/*` contracts or auto-writing canonical facts from automatic capture.  
> **Related:** `docs/superpowers/specs/2026-11-12-mimir-1.7-to-2.0-roadmap-design.md` (§5 1.8, §5.5, §6 1.9 Adapter Contract), `docs/superpowers/plans/2026-11-16-mimir-1.8-hooks-stm-heat.md`, `docs/BENCHMARK-COMPARE.md`, `mimir_v8/adapters/hooks_a_tier.py`, `mimir_v8/learning.py`, `mimir_v8/classifier.py`, `mimir_v8/api.py`

## 1. Problem statement

1.8.0 delivers A-tier hook ingest + STM candidate crystallization (`/v8/hooks/session-start`, `/v8/hooks/session-end`) and heat signals, but two extension surfaces are still effectively hardcoded:

- **Agent integration path:** `mimir_v8/adapters/hooks_a_tier.py` is a fixed, declarative table (`claude-code`, `codex`) with a single payload builder. Adding a new harness/agent today means editing core adapter code and re-encoding conventions (endpoints, connector identity, idempotency shape, capability assumptions).
- **Memory sources:** `ConversationEnvelope`/`LearningService` accept a broad-but-implicit connector set, `mimir_v8/classifier.py` owns a static `connector_type -> source_category` map, and ingestion semantics (conversation vs knowledge/doc vs event-like sources) are not modeled as an explicit, registrable contract. Future sources (other agent transcripts, tool/task logs, external KB sync, event streams, Thor/Odin automatic collection, etc.) need a stable onboarding path that preserves DLP, idempotency, review-before-fact, and fail-closed guarantees.

**Design goal:** define and freeze the contracts, registries, invariants, and rollout plan so 1.8.x can onboard new agents and new memory sources by registration/configuration and narrow adapter/connector implementations—without per-source core rewrites and without weakening governance.

---

## 2. Non-goals (for this design / 1.8 implementation slice)

- No automatic write to canonical `facts` from hooks, STM, or any auto-captured source (candidates/review artifacts only, per spec §5.1, §10).
- No breaking change/removal of existing `/api/*` or `/v8/*` routes and payloads. Dashboard v5/backend contract changes remain out of scope.
- No harness-specific business logic in core storage/learning paths; core consumes normalized envelopes/items + declared policy, not raw harness payload quirks.
- No cross-principal data leakage: adapters/connectors never bypass auth, owner boundary, or ACL/visibility.
- No weakening of fail-closed behavior (DLP before persist/candidate; no tombstone/ledger success => no deletion/purge; no LLM => deterministic Tier-0 path only).
- 1.9 installer/`mimir install-adapter` CLI and full per-harness config generation are **specified for compatibility** but not required to ship complete in this 1.8 groundwork slice (see §9).

## 3. Current state (baseline)

| Concern | Current implementation | Extension gap |
|---|---|---|
| Hook API | `GET /v8/hooks/session-start` (read-scoped bootstrap), `POST /v8/hooks/session-end` (ingest, scope `ingest`, owner boundary) in `mimir_v8/api.py` | Generic and stable, but no server-side adapter manifest/introspection and no capability registry. |
| Hook adapter | `HOOKS_A_TIER` dict + `build_session_end_payload(...)` in `mimir_v8/adapters/hooks_a_tier.py` | Hardcoded agents; no register/discover; no capability/capacity metadata model; payload builder not per-adapter. |
| Conversation ingest | `ConversationEnvelope`/`ConversationMessage` + `LearningService.ingest_conversation/session_end` in `mimir_v8/learning.py`; DLP, fingerprint idempotency, `conversation_sources/messages`, event emission, session_end creates 1 candidate from redacted text | Envelope permits any non-empty `connector_type` but source semantics/classification/allowance are static and implicit. |
| Source classification | `mimir_v8/classifier.py` static `SOURCE_CATEGORY_MAP` (`conversation`/`external_info`/`knowledge_doc`/`unknown` quarantine) | No runtime registration, no per-source ingest policy (modes/retention/extraction eligibility) bound to the type. |
| Identity/auth | Token/principal scopes (`read`,`ingest`,`write`,`delete`,`manage`), `can_act_as` owner boundary on hook/ingest bodies | Correct boundary exists but adapter contract must formalize principal/owner mapping rules. |
| Storage | `conversation_sources` stores `connector_type/connector_id/session_id/owner_principal/memory_mode/retention_class/source_category/...`; `sources.source_kind` for generic sources | Sufficient base; extensibility should prefer additive metadata over schema churn. |

**Invariants to preserve:** `session_end` rejects `memory_mode="explicit"`; auto-capture crystallizes candidates only (`auto_captured_requires_review`/review paths), never facts; DLP redaction before candidate/storage; idempotent replay returns same identities; retention/tombstone/ledger operations fail closed.

## 4. Design A — Agent Adapter Contract & Registry

### 4.1 Concepts and separation of concerns

- **Agent/Harness adapter:** a harness-facing integration that knows *how an agent runtime talks to Mímir* (lifecycle hooks/capabilities, endpoint usage, how to form a valid hook/envelope payload, identity conventions). Adapters are primarily **client-side shims** over stable backend endpoints.
- **Connector/source (Design B):** knows *what kind of memory/source the payload represents* and how it is governed/normalized. A single agent session typically uses a conversation connector (e.g. `external_agent`) carried by an agent adapter; the adapter selects/mints connector identity but does not redefine source governance.

This separation keeps backend ingest policy (B) independent from harness wiring (A) while allowing composition.

### 4.2 Adapter contract (normative)

Introduce a first-class adapter model in `mimir_v8/adapters/` (in-process), compatible with the 1.9 declarative manifest direction.

**Required identity/metadata fields**
- `adapter_id: str` — stable id (e.g. `claude-code`, `codex`, `opencode`, `hermes`, `mirasim`, `<vendor>-<agent>`). Kebab-case, globally unique in registry.
- `display_name: str`
- `version: str` — adapter contract version (semver-ish string).
- `tier: Literal["A","B","C"]` — A hook-lifecycle, B MCP/tool-triggered, C explicit/HTTP only (per roadmap §5.2).
- `status: Literal["builtin","experimental","deprecated"]`
- `description: str`

**Capability declaration** (`capabilities`, explicit booleans/enum set)
- `session_start: bool` — can obtain bootstrap payload (standard: `GET /v8/hooks/session-start`, scope `read`).
- `session_end: bool` — can submit end-of-session ingest + STM crystallization (standard: `POST /v8/hooks/session-end`, scope `ingest`).
- `post_tool_use: bool` — can emit tool/trajectory summaries (future; 1.8 A-tier may declare false except where implemented).
- `trajectory_capture: bool`
- `explicit_remember_assist: bool` — may guide user to `remember()`; **never** implies auto-fact write or `memory_mode=explicit` on hooks.
- `supports_incremental_flush: bool` — can send mid-session deltas (future; requires idempotency strategy).

Minimum viable adapter: at least one of {`session_start`, `session_end`, `explicit_remember_assist`} true; C-tier may be explicit-only.

**Endpoint/binding**
- `hooks.start`: `{method: "GET", path: "/v8/hooks/session-start"}` (default) or `null` if unsupported.
- `hooks.end`: `{method: "POST", path: "/v8/hooks/session-end"}` (default) or `null`.
- Future optional additive endpoints (e.g. trajectory) declared but unused until implemented; **must not** require changes to existing endpoints.

**Connector & payload conventions**
- `default_connector_type: str` — must resolve to a registered/allowed conversation-capable source connector (Design B), typically `external_agent` or a dedicated registered type.
- `connector_id_template: str` — deterministic template, e.g. `{adapter_id}:{runtime_instance}` or `{adapter_id}:{host}`; adapter/runtime supplies concrete value.
- `session_id_source: "runtime"|"generated"|"none"` — who provides `session_id`.
- `default_memory_mode: Literal["observe","never"]` — **`explicit` is forbidden** for hook/session-end auto paths (enforced by existing API/service validation; adapter must not emit it).
- `default_retention_class: str` — e.g. `short` for session STM (validated against `RETENTION_CLASSES`).
- `owner_principal_mode: Literal["authenticated_principal","explicit_body","mapped"]` with rule: resolved `owner_principal` **must** equal or be permitted by the authenticated principal (`identity.can_act_as`); adapters must never impersonate across owners.
- `idempotency`: `{key_strategy: "session_end"|"message_range"|"external_event"|"custom", key_template?: str}`. For `session_end`, key must be stable per session-end emission so replay is safe (current behavior).

**Payload builder hook (in-process)**
- Provide `build_session_start_request(context) -> request spec` (default: none/bodyless GET) and `build_session_end_envelope(context) -> ConversationEnvelope-compatible dict` per adapter, reusing/aligning with existing `build_session_end_payload` semantics.
- Builders **must** emit only fields accepted by `ConversationEnvelopeBody`/`ConversationEnvelope` and must not inject raw secrets or bypass DLP expectations (server remains authoritative for redaction/validation).

**Observability/metadata (additive)**
- Adapters may set `metadata.agent_type = adapter_id` and `metadata.adapter_version` inside envelopes; servers must tolerate unknown metadata keys (current models allow `metadata: dict`).

### 4.3 Registry & discovery

Create `mimir_v8/adapters/registry.py` (or equivalent cohesive module) providing:

- `AdapterSpec` (dataclass/typed model) + validation (`validate_adapter_spec`).
- In-process registry: `register_adapter(spec, *, override=False)`, `get_adapter(adapter_id)`, `list_adapters(*, tier=None, capability=None)`, `require_adapter(adapter_id)`.
- **Built-in registration:** on import/init, register `claude-code` and `codex` (migrated from `HOOKS_A_TIER`, preserving current paths/behavior) so existing behavior is unchanged.
- **Declarative manifest loading (additive, 1.8 groundwork):** support loading adapter manifests from a configured path (e.g. `MIMIR_ADAPTERS_DIR` or `config/adapters.d/*.yaml|json`) mapping to `AdapterSpec`. This aligns with roadmap §6/§12 (`mimir_v8/adapters/*.yaml`) without requiring the 1.9 installer. Parsing must be strict and fail closed on invalid manifests (log/raise at load, never silently partially register unsafe config).
- **Plugin/entry-point hook (future-ready):** define an optional discovery point (e.g. Python entry point group `mimir.adapters`) invoked only when explicitly enabled; disabled by default in 1.8 to limit supply-chain risk.

`mimir_v8/adapters/hooks_a_tier.py` becomes a compatibility layer re-exporting built-ins and `build_session_end_payload` (delegating to `claude-code`/generic builder) to avoid breaking existing imports/tests.

### 4.4 Server-side introspection (additive, optional in 1.8)

May add **read-scoped** `GET /v8/hooks/adapters` returning registered adapter manifests/capabilities (no secrets, no tokens). This is additive; absence is acceptable if deferred, but the contract above is the source of truth.

### 4.5 Identity, auth, and safety rules (normative)

1. **Authenticated principal is authoritative:** adapter-declared identity cannot override token identity. `owner_principal` in hook payloads must satisfy `identity.can_act_as(owner_principal)` (already enforced); adapters must document mapping.
2. **No cross-owner capture:** an agent adapter running as principal P may not ingest/session-end for principal Q unless explicitly delegated and authorized by server policy (current behavior: rejected).
3. **No privilege escalation:** adapters only guide clients to call existing scoped endpoints (`read` for start/bootstrap, `ingest` for end); no manage/delete scopes implied.
4. **Explicit memory boundary:** `memory_mode="explicit"` is not permitted on session/hook auto-capture paths; adapters must route explicit user intent to the governed `remember()` flow.
5. **Auditability:** envelopes should carry `metadata.agent_type`/`adapter_id` and `connector_id` so ingestion events and sources are attributable.

### 4.6 Tier behavior summary

| Tier | Typical harness | Required now | Optional/future | 1.8 baseline |
|---|---|---|---|---|
| A Hook | Claude Code, Codex | `session_start` and/or `session_end` via `/v8/hooks/*` | `post_tool_use`, trajectory, incremental flush | Implemented/declared for `claude-code`,`codex` |
| B MCP | Cursor/Zed/Windsurf, OpenCode (MCP) | explicit/MCP-triggered calls; may use hooks where available | session_end assist, remember assist | Contract + registration path; runtime wiring incremental |
| C Explicit | scripts, DeepSeek/manual, generic HTTP | governed explicit ingest/remember | — | Always supported via existing APIs + adapter manifest for conventions |

## 5. Design B — Memory Source / Connector Extensibility

### 5.1 Goals

- Make every ingested memory source **typed, classified, and policy-bound** by registration rather than ad-hoc string handling.
- Support multiple ingest pipelines (conversation/session STM, knowledge/doc items, future event/tool-log streams) behind stable normalization contracts.
- Preserve: DLP before persist/candidate, idempotency/fingerprints, review-before-canonical-fact for auto capture, owner/ACL boundaries, retention/audit, and fail-closed behavior.

### 5.2 Source connector contract (normative)

Introduce `mimir_v8/sources/` (or `mimir_v8/connectors/`) with a registry and a connector specification/protocol.

**Connector identity & classification**
- `connector_type: str` — stable source type key stored in `conversation_sources.connector_type` / item provenance (e.g. `hermes_cdc`, `external_agent`, `file`, `rss`, `web`, future `agent_transcript`, `tool_log`, `kb_sync`, `event_stream`, `thor_auto`, `odin_auto`).
- `source_category: Literal["conversation","external_info","knowledge_doc"] | "unknown"` — aligned with classifier categories; `unknown` means quarantine.
- `display_name`, `description`, `status`.

**Pipeline & capability declaration**
- `ingest_kind: Literal["conversation","knowledge_item","event","hybrid"]`
  - `conversation`: normalizes to `ConversationEnvelope` -> `LearningService.ingest_conversation` and/or `session_end` (STM candidate path).
  - `knowledge_item`: normalizes to knowledge/document ingest item (e.g. `/v9/knowledge/items` / `CreateKnowledgeItem`) or a governed candidate-extraction path; **not** direct fact write.
  - `event`/`hybrid`: normalizes to one or more of the above via explicit, declared rules.
- `interaction_mode: Literal["push","pull","stream","manual"]`
- `supports_incremental: bool`, `supports_delete_sync: bool` (tombstone/alignment semantics), `supports_schedule: bool` (CDC/cron hints, metadata only unless scheduler exists).

**Normalization contract**
- `normalize(raw, *, context) -> list[NormalizedRecord]` where each record is one of:
  - `NormalizedConversation`: `{envelope: ConversationEnvelope-compatible dict|object, mode: "ingest"|"session_end"}`.
  - `NormalizedKnowledgeItem`: knowledge-item payload for governed ingest/review path.
  - (Future additive types allowed only if they terminate in governed candidate/review/storage flows.)
- Normalizer responsibilities: structural mapping, stable `connector_id`/`session_id` derivation where applicable, message/item ordering, timestamp mapping, and metadata enrichment (`source_uri`, `title`, provenance). Normalizers **must not** perform final DLP bypass, and **must not** emit canonical facts.

**Idempotency & provenance (normative)**
- Declare `idempotency_strategy`: one of `external_id`, `content_fingerprint`, `session_turn_range`, `source_cursor`, or `composite`, with required key fields.
- `build_idempotency_key(record, raw) -> str` must be deterministic for the same logical input; replays must map to the same stored source/run/candidate identities per existing service guarantees.
- Declare `source_hash_strategy` and provenance fields to retain (`source_uri`, external ids/cursor in metadata) for audit and replay.

**Governance & defaults**
- `allowed_memory_modes: set[str]` subset of `MEMORY_MODES` (e.g. conversation auto-capture: `{"observe","never"}`; explicit-only sources may allow governed explicit handling but hooks/session_end remain `explicit`-free).
- `default_memory_mode`, `default_retention_class` (validated).
- `auto_candidate: bool` — whether normalized conversation/session end should crystallize STM candidate via governed path (default true for session_end-like conversation capture; never direct fact).
- `extraction_policy: Literal["none","candidate_only","governed_review"]` — auto sources must resolve to `candidate_only`/review-gated extraction, never `direct_fact`.
- `quarantine_on_unknown: bool = True` and `trust_tier`/handling hints for classifier/category consumers.

### 5.3 Source registry & classification evolution

- `SourceRegistry`: `register_source(spec)`, `get_source(connector_type)`, `list_sources(...)`, `resolve_category(connector_type)`, `policy_for(connector_type)`.
- **Built-ins registered explicitly** to match current behavior: `hermes_cdc`, `external_agent`, `workbuddy` (conversation), `rss`, `web`, `searxng` (external_info), `feishu`, `file`, `document`, `vault` (knowledge_doc) — preserving `classifier.SOURCE_CATEGORY_MAP` semantics.
- `mimir_v8/classifier.py` becomes a compatibility facade delegating to the registry (`classify`, `is_*`, `CONVERSATION_TYPES` etc. derived from registered specs) so existing callers/tests remain valid.
- **Unknown/unregistered `connector_type`:** classify as `unknown/quarantine`. Normalization/ingest of unknown types is **fail-closed for auto-promotion**: may be stored only under quarantine-safe handling if an explicit, reviewed path allows, but must not produce auto candidates/facts nor bypass policy. (Concrete enforcement point: `LearningService.ingest_conversation/session_end` and any extraction pipeline consult registry policy before candidate crystallization or downstream promotion.)
- **Registration sources (1.8):** built-ins + optional declarative config (e.g. `config/sources.d/*.yaml|json` or env-selected file) with strict validation. Entry-point/plugin loading optional and disabled by default (same risk posture as adapters).

### 5.4 Envelope & validation alignment

- `ConversationEnvelope.validated()` (and `ConversationEnvelopeBody` handling) should remain backward compatible for currently valid inputs. Policy tightening is registry-driven:
  - accept non-empty `connector_type` strings as today; resolve policy via registry;
  - if policy marks type as disallowed for the requested pipeline/mode (e.g. `memory_mode` not in `allowed_memory_modes`, or session_end on a non-conversation/quarantined type without explicit allowance), raise `ValidationError` (fail closed).
- Prefer additive metadata (e.g. `metadata.source_connector`, `metadata.agent_type`, `metadata.ingest_kind`) over required schema changes. Any DB changes must be additive, idempotent migrations with safe defaults (legacy rows preserved).

### 5.5 Pipelines, DLP, and governance invariants

1. **DLP first:** all text/content entering stored conversation/messages, knowledge items, or candidate content passes `redact_text`/equivalent DLP before persistence and before candidate crystallization (server-side, non-bypassable by connector claims).
2. **No auto-facts:** auto/observed ingestion yields stored source records and/or STM candidates only; canonical facts require existing review/commit or explicit governed `remember()` flows.
3. **Idempotent & replay-safe:** `(idempotency_key, fingerprint/content hash)` semantics preserved; replay returns prior identities, never duplicates sources/candidates/facts.
4. **Owner & scope:** `owner_principal` bound to authenticated actor per scope; connectors cannot widen visibility/egress.
5. **Retention & audit:** honor `retention_class`/memory mode policy; emit/retain ingestion events; retention/deletion remains ledger/tombstone-fail-closed.
6. **Deterministic fallback:** no LLM in the normalization/governance-critical path; extraction beyond Tier-0 follows existing fail-closed rules.

### 5.6 Scheduling / pull & incremental sync (contract-level)

For future `pull|stream|schedule` connectors (CDC, KB sync, event feeds): the connector spec declares cursor/checkpoint fields, poll cadence hints, and delete/tombstone alignment expectations. 1.8 groundwork defines the contract and config shape; actual schedulers/workers (and Thor/Odin automatic collection wiring) implement against it incrementally, with idempotent cursors and observable lag/error reporting. Thor/Odin automatic collection (spec §5.5 gap) is the **first targeted onboarding exemplar** once a concrete producer is available.

## 6. Unified model (A × B composition)

| Dimension | Agent Adapter (A) | Memory Source Connector (B) |
|---|---|---|
| Primary concern | Harness lifecycle/wiring, how to call hooks/APIs, capability declaration | Source typing, normalization, governance, classification, idempotency |
| Typical artifact | Adapter manifest/spec + payload builder | Source spec + normalizer + policy |
| Example composition | `claude-code` adapter (A-tier) emits session-end envelope with `connector_type=external_agent` | `external_agent` conversation source (B) classifies as `conversation`, allows `observe/never`, candidate-only extraction |

Rules:
- Adapters **select** a registered source connector and supply valid connector identity/provenance; they do not invent governance.
- A new agent usually needs: (1) adapter registration (A), (2) reuse of an existing source connector or registration of a new one (B) if semantics differ.
- A new non-agent memory source usually needs only (B) plus a producer/ingest caller (script, CDC worker, or future scheduler).

## 7. Data model & API impact (additive, backward-compatible)

- **No breaking route/payload changes.** Existing `/v8/hooks/*`, `/v8/ingestion/conversations`, `/v8/learning/*`, `/v9/knowledge/items` remain valid.
- **Metadata (preferred):** encourage `metadata.agent_type`, `metadata.adapter_id`, `metadata.adapter_version`, `metadata.source_connector`, `metadata.ingest_kind`, `metadata.provenance` (opaque/extensible). Existing JSON metadata columns/fields already accept arbitrary keys.
- **Optional additive endpoints (1.8.x, if low-risk):** `GET /v8/hooks/adapters` (read-scoped manifest listing) and/or `GET /v8/sources/connectors` (read-scoped registry view). Defer if they complicate scope; contract/registry can exist in-process first.
- **Schema:** avoid mandatory migrations in the first slice. If needed later, only additive nullable columns/indexes or metadata usage; all migrations idempotent and backfill-safe (no fabricated history), consistent with existing migration discipline.
- **Config:** additive config locations for adapter/source manifests (documented), disabled-by-default external loading where appropriate.

---

## 8. Security, privacy, and reliability considerations

- **DLP/redaction non-bypassable:** enforced server-side on ingest/session_end and before candidate creation.
- **Fail-closed defaults:** unknown source types quarantined for auto-promotion; invalid manifests rejected; missing tombstone/ledger on retention => no delete.
- **Least privilege:** hook start requires `read`, hook end/ingest require `ingest`, remember flows require appropriate write scopes; owner boundary enforced.
- **Supply chain:** dynamic plugin/entry-point loading off by default; declarative manifests schema-validated.
- **Idempotency/replay storms:** stable keys + fingerprint conflict detection (`ConflictError` on key reuse with different content) prevent duplicate or ambiguous state.
- **Observability:** structured audit events include connector/adapter attribution via existing event payloads/metadata; registry exposes declared capabilities for debugging.

## 10. Acceptance criteria (design considered satisfied when implemented)

- [ ] New agent can be integrated by adding a validated adapter spec/manifest + (if needed) payload builder, using existing `/v8/hooks/session-start|session-end` without modifying core ingest/storage logic.
- [ ] New memory source can be integrated by adding a validated source spec/normalizer + policy registration, routing into an existing governed pipeline (conversation ingest/session_end or knowledge item) without modifying core DLP/idempotency/review invariants.
- [ ] Built-in adapters/sources behave identically to pre-refactor baseline (compat tests pass).
- [ ] Unknown/quarantined sources cannot auto-promote to candidates/facts; disallowed modes/paths fail closed with validation/policy errors.
- [ ] Auto-capture paths never write canonical facts; `memory_mode="explicit"` remains rejected on hook/session-end paths; DLP and idempotent replay guarantees hold (proven by tests).
- [ ] Registry/manifests expose capabilities and policy clearly enough to generate 1.9 adapter install artifacts without redesign (forward-compatible with roadmap §6/§12).

## 11. Decisions (finalized)

| Decision | Rationale |
|---|---|
| Separate **agent adapter** (harness wiring/capabilities) from **memory source connector** (typing/normalization/governance), composed at ingest boundary | Matches existing architecture (generic hook endpoints + envelope/source classification) and avoids coupling harness quirks to storage policy. |
| Keep `/v8/hooks/*` and ingest APIs stable; extend via registries, manifests, and additive metadata/introspection | Preserves backend contract and enables incremental onboarding (including 1.9 installer) without breaking clients. |
| Registry-backed classification/policy replaces scattered static checks (with compat facades for `classifier`/`hooks_a_tier`) | Single source of truth for category, allowed modes, retention defaults, and extraction/promotion eligibility. |
| Unknown sources default to **quarantine + fail-closed for auto-promotion** | Prevents silent trust of new/unreviewed connectors while allowing explicit, governed handling later. |
| Auto-capture remains **candidate/review-only**, never canonical facts; explicit writes stay on `remember()` | Preserves core Mímir governance (spec §5.1, §10) and prevents black-box memory pollution. |
| Declarative manifests/config are additive and strictly validated; dynamic plugins off by default | Forward-compatible with 1.9 Adapter Contract/YAML while limiting runtime risk in 1.8. |
| Thor/Odin automatic collection treated as a first memory-source onboarding exemplar under the same governed pipeline | Converts spec §5.5 gap into a concrete, testable acceptance target rather than a bespoke core path. |
