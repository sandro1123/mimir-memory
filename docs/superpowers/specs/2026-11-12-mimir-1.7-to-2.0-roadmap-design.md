# Mímir 1.7.0 → 2.0 路线图：Obsidian Bridge 收尾 + 自动记忆 + 多 Agent 适配

> **文档日期**：2026-11-12
> **状态**：Design Spec（草案，待人工批准）
> **前置**：五条已绿 PR 待合并（#41 #43 #45 #46 #47）；本稿不合并代码
> **当前基线**：v1.6.0 `SCHEMA_VERSION=21`，master `0635ceb`

## 1. 结论先行：版本趋势一句话

Mímir 不做 mem0 式“全自动产品化渠道”，走可信底座路线：

- **1.7.0 Obsidian Bridge（双向反哺）**：把 1.6 之前所有修复收尾，提供“人类侧知识中枢”；是 1.8 自动记忆的前置——自动记忆的产物要能回流到库里被人类看见，否则自动化只是在后台黑盒堆积。
- **1.8.0 自动记忆（Auto-Capture + 分层热度）**：补齐最大缺口：其他 Agent 不用手动 `mimir_remember`，会话自动沉淀为短时→长时记忆；检索热度按真实复用而非静态半衰期。
- **1.9.0 Harness 家族（多 Agent 适配标准化）**：把 Claude Code / Codex / Hermes / Mirasim / Cursor/Zed 的接入从“各写一遍”变为声明式 Adapter，第三方接得进来。
- **2.0.0 双时态 + 统一脑**：valid_time / transaction_time、可签谱系、双池一桥收官。

每一版都有独立可验收的收官判据；后一版不依赖前一版“感觉做完”，只依赖可证伪的 artifact。

## 2. 为什么这个顺序（优先级推理）

| 顺序 | 理由（来自实测/判例） |
|---|---|
| 先 Obsidian（1.7）| 自动记忆若无可信回流面，等于把“来者不拒”的黑盒搬到后台——违背 Mímir 招牌。且 1.7 的回流闸（三重判据+自我摄入防护）是自动记忆不可绕过的准入前置。 |
| 再自动记忆（1.8）| 用户所有 Agent 切换成本的根因：学完要重复教。其他适配器（1.9）必须建立在一个“自动捕获协议”之上，否则每个 harness 各自为政。 |
| 再多 Agent 适配（1.9）| 1.8 的自动记忆协议确定后，适配工作量降为“填表”。反之先做适配，必然返工。 |
| 最后双时态（2.0）| 双时态改变 schema 查询语义，宜在记忆流量和接入面都稳定后做，避免迁移期双重变数。 |

## 5. 1.8.0 自动记忆（短时 + 长时）

> **本计划最核心的新增，也是 #34 的升级版。** #34 只到“钩子把会话塞进来”；本节把“塞进来”拆成短时+长时两层，明确什么进上下文、什么进库、什么被遗忘。

### 5.1 分层模型（Mímir 版映射）

| 层 | 对应 dsh / Letta | Mímir 落点 | 存活 | 进上下文方式 |
|---|---|---|---|---|
| **STM 短时** | dsh L1 hot / Letta active context | `session_episode`（会话作用域，TTL 24h，未结晶不进 canonical） | 短暂 | 仅本会话内可被 `proactive_wake` 按需注入 |
| **LTM staging 长时暂存** | dsh L2 consolidate / DL1 未引用 | **学习候选**（既有 `candidates` 管线） | 数天 | 不注入；只进评审面 |
| **LTM canonical 长时** | dsh DL3 / Letta archival | **facts**（事件溯源） | 长期 | 经三段渐进披露准入后注入（当前路径，不变） |
| **LTM view 视图层** | dsh L3（只看不存） | **core_memory 注入面**（既有） | 计算时 | 注入时按需从 canonical 投影，**不新增真相源** |

**关键纪律**：STM 在会话结束时**自动结晶为候选**（走既有 Tier-0/1/2 判重→评审→入库，不直写 facts）；“自动获取” ≠ “自动入库”——AGG 全自动，UPDATE/DELETE 永不自动（沿用 1.5.0 判词）。

### 5.2 自动捕获触发（按 harness 能力分档）

| 档 | 触发器 | 覆盖面举例 | 捕获协议 |
|---|---|---|---|
| **A 钩子型**（最完整）| `SessionStart` + `PostToolUse` + `SessionEnd` | Claude Code / Codex（原生 hooks）| SessionStart 拉 `/v15/bootstrap`；SessionEnd POST `ingest_conversation`（结构化消息数组）；中间工具调用只记 trajectory 摘要 |
| **B MCP 型** | `mimir_*` 工具被显式调用 | Cursor / Zed / Windsurf（MCP-only，无 hooks）| 工具调用本身即触发记录；同一会话内无钩子时降级为“B 档” |
| **C 显式型**（兜底）| `/remember`、CLI、`POST /v8/ingestion/conversations` | 任意 Agent / 脚本 | 行为不变，但 STM 也会被同一套结晶逻辑消费 |

**评估指标**（每档分别统计，不混在一起）：触发覆盖率（会话中自动捕获消息比例）、结晶产出率（STM→候选转化）、候选转正率、误捕获率（被评审 reject 的占比）。

### 5.3 热度系统（吸收 dsh 的 1+3）

三个具体改动，均需数据库迁移与反向注入钉：

1. **半衰期按活跃日**：`_decay_factor` 不再只读静态 `DECAY_HALF_LIFE`；有效半衰期 = `base * f(active_days)`，其中 `active_days = log2(1+strength)`，`strength` 来自重复命中记录。
2. **`spacingQuality`**：两次命中的间隔越长，对热度的提升越大：`q = min(1, 0.15 + 0.85·log2(1+ratio))`。
3. **计数双轨（最重要的防回声措施）**：
   - `fusionCount` = 内容重复次数（语义相似，累计式）
   - `recallCount` = `mem.attend(ids)` 确认使用次数**而非**“搜过 N 次”
   - 两者之间写 `search_feedback` → Mimir 的生产 `search_feedback` 表**目前只写不读**（`evolve.py` 写，`query.py`/`relevance.py` 无消费）——补上“读”的接线，让它进入 `_decay_factor`。
   - **对比诚实**：dsh 用热度（跨越 1 天重复 0.35 / 14 天 0.70）实测证明间隔加权对长期召回有增益；Mimir 尚无对等实测，上线前须在 `docs/BENCHMARK-PROTOCOL.md` 下补半日实测（差距 #26 同款“先量后写”纪律）。

**legacy 数据迁移**：对现有 `search_feedback` 按 `fact_id` 回填计数列（缺省为 0，不捏造），保证老态可回放。

### 5.4 “没模型就不摘要 / 没账本就不删”两派的 fail-closed

- 无 LLM 时，只走 Tier-0 确定性路径（content_hash 合并），**不降级为“全文暂存”**。
- 衰减删除前先写 `tombstone_snapshots` 等价账本，写失败保持不删（现 `retention.py` 已有类语义，须补反向注入钉证明“账本写失败 → 不删”）。

## 6. 1.9.0 多 Agent 适配（harness 家族标准化）

#36（mimir-mcp 在主流客户端的设置注入）与 #25 Epic（Harness 家族：skill → MCP → Cursor/Zed → Codex）合并推进：

**统一 Adapter Contract（新的 `mimir_v8/adapters/`）**
```yaml
# adapters/<name>.yaml
name: claudecode
kind: hook            # hook | mcp | explicit
capture: SessionStart+SessionEnd
bootstrap: /v15/bootstrap
inject: settings.json
```
每个 harness 登记一份；`mimir-mcp` 安装器读它生成各客户端配置（Claude Code `.claude/settings.json` / Codex / Cursor / Zed / Mirasim）。MCP 工具面继续统一在 `mimir_v8/mcp.py`（已 32 个工具）。

**分期（按接入成本排序）**
1. **MCP-only 档**（Cursor / Zed / Windsurf）：下发 `mcpServers` 片段即可，见 #36 验收项。
2. **钩子档**（Claude Code / Codex / Hermes Agent）：SessionStart 注入 + SessionEnd 自动摄入（即 1.8 的 A 档）。
3. **Mirasim 档**（自家）：Server 侧预取（Hermes `memory.provider: mimir` 已有底子）；验收是“换 Agent 不换脑”。

**#30 全闭合的联动**：新 Agent 三步 onboarding —— `POST /v8/principals/register`（签发 token）→ 按 adapter 档装载 → `/v15/bootstrap` 接收 L0/L1。#30 PR（#43）已实现 register/revoke 与持久化 roster，本版只补适配器与端到端测试。

## 7.5 还能加什么（本版按“可证伪”纪律补强的功能点）

以下不是新方向，而是沿用当前底座、补当前真实缺口，每条都带触发器、消费点、统计面。**不加“显得完整”的功能。**

| # | 功能 | 现状（实测） | 触发器 | 消费点 | 统计面 |
|---|---|---|---|---|---|
| F1 | **自动记忆 STM/LTM 分层**（#34 扩大版） | `ingest_conversation` 在，STM 无（见 5.1） | SessionStart/End、MCP 工具调用 | 结晶→候选→评审→入库 | 触发覆盖率、误捕获率、候选转正率 |
| F2 | **热度双轨（融合次数 vs attend 次数）** | `search_feedback` 只写不读，`_decay_factor` 静态 | `search_feedback` 写入 | `_decay_factor`、TopK 排序 | 重复间隔加热实测对比 |
| F3 | **Adapter Contract（声明式接入）** | 各 harness 自拼 settings.json（#36 未收） | 安装时 | MCP 注入器、skill 下发 | 三个 harness 端到端一遍 |
| F4 | **自动自检（持续陪跑）** | 有手动跑分入口，缺持续陪跑 | 定时 | `evolve_report`、评测报告回放 | GOLDEN_FLOORS 门禁 |
| F5 | **过期即遗忘（ledger 先行）** | `retention.py` 有类语义，缺反向注入钉 | decay-scan 定时 | tombstone 账本 | 缺失账本=不删（证明） |

**没在表里的（刻意不做）**：情绪识别、意图推断、跨用户画像合并——这些是“显得多”的功能，违背“非必要不加”纪律。

## 9. 留给用户的三个决策点（按重要性排序）

1. **P1–P4 路径**（1.7 stage2 阻塞）：推荐 P1 先行、P2 随后——1.7 代码以 P1 全量落地，P2 在 1.8 的“脱敏+统一 `egress_policy`”治理项里一并解决，避免 1.7 台在一个决策上。
2. **是否接受“STM 不直写 facts”**：自动记忆只产候选，入库仍走评审；若用户想要“结晶即入库”的强自动化，则须放弃 1.5.0 “UPDATE/DELETE 永不自动”的判词，需显式翻案。
3. **Adapter 首批名单**：默认 {Claude Code, Codex, Hermes, Mirasim}，Cursor/Zed 低成本顺带；OpenClaw 等长尾待 1.9 之后。

## 10. Non-Goals / 反目标重申

- 不做“全自动直接写库”（绕过候选评审的自动记忆）。
- 不把脱敏扫描做成“标签替代品”（§7.7 的教训：标签挡不住明文密钥）。
- 不把检索热度做成“搜得多就热”（回声闭环是这版的第一 anti-pattern）。
- 不引入 JSON 文件锁与外部向量库（SQLite WAL + chroma 足够，避免与 adr/照单全收的 dsh 锁模型混接）。

## 11. 本稿的假设声明（需要核对）

- 假设 n100 上“真实跨 Agent 切换”的频率依然高（84% 记忆锁死），否则自动记忆的 ROI 需重算。
- 假设 `search_feedback` 的回填迁移成本可承受（历史数据量未知，需上 n100 实测）。
- 假设无 LLM 时“只走 Tier-0”不会饿死召回（生产已在 jog 常态，待观测证实）。
