# Mímir 1.5.0 实施计划：联邦共享、退役 mentor 与 Agent 零配置自举

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 落地 Mímir 1.5.0 核心能力，打破 84% 记忆锁死孤岛，平滑退役 `mentor` 并由主 Agent `heimdallr`（Heimdallr-EX）无缝继承 469 条历史事实，支持动态 Agent 零配置准入与 `/v15/bootstrap` 自举握手。

**Architecture:** 
1. 继承别名梯（Principal Alias Ladder）：在 `auth.py` 与 `store.py:can_access` 中注入别名映射，使 `heimdallr` 零数据库迁移直接继承 `mentor` 的读写权限。
2. 领域级共享放宽（Domain-level Sharing Read Gate）：非私密域（`knowledge`, `infrastructure`, `tech_support`）的参考事实对已认证的 Agent 开放跨 Agent 共享阅读，解决 84% 锁死。
3. 动态 Agent 零配置准入与自举（Dynamic Onboarding & Bootstrap）：请求头通过 `X-Mimir-Agent` 动态声明新 Agent，下发受控权限；提供 `GET /v15/bootstrap` 端点一键下发 L0 铁律、L1 偏好与领域存量大纲。

**Tech Stack:** Python 3.10+, FastAPI, SQLite3 (FTS5), pytest, REST/MCP.

**Spec:** `docs/superpowers/specs/2026-10-26-mimir-2.0-unified-brain-design.md`

## Global Constraints

- **不可篡改事件溯源**：严禁直接用裸 SQL UPDATE 破坏 `memory_events` 与哈希链表结构；历史事实保持原始 `owner_principal='mentor'`，通过 ACL 别名继承生效。
- **发布闸门保持严密**：版本号升级必须在 `mimir_v8/schema.py`、`pyproject.toml`、`dashboard/backend/main.py`、`tests/test_r8_release.py` 四方同步。
- **预算诚实不回退**：检索与自举返回均不得包含虚假成功占位符（stub），截断必须伴随显式丢弃计数。
- **单向物理安全保护**：私密域（`personal`）与高敏感（`restricted`）事实必须维持原有严格 owner-only 隔离。

## Review Focus

1. **别名权限冒名攻击**：非 admin 调用方传入恶意别名试图伪装 `mentor` 时，系统必须坚决拦截（fail-closed），仅限已绑定别名的受信任 Principal 拥有继承权。
2. **私密域穿透泄露**：放宽技术域（`knowledge`）共享时，个人域（`personal`）和密钥类敏感事实绝对不能被任何其他 Agent 召回。
3. **动态 Agent 提权风险**：`X-Mimir-Agent` 自注册的新 Agent 不能自动获得 `admin` 或跨主体删除权，默认仅授予受控 `read` 与候选提交权限。
4. **自举端点超限膨胀**：`/v15/bootstrap` 端点必须控制单次 Payload 体积（< 2KB / 500 Token），严禁直接倾倒全库事实，只能抽取 L0 铁律、L1 偏好与聚合统计。
5. **历史测试回归**：全仓 444+ 存量测试必须保持零新红，Windows 平台 41 条已知平台噪音不得增加。
