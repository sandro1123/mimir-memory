# Mímir 1.8.0 Hooks, STM, and Heat Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver 1.8.0 "brain auto-capture + heat": A-tier SessionStart/SessionEnd hooks with automatic STM candidate capture (never auto-writing facts), and recall dynamics that combine time decay with spacing/usage evidence read from `search_feedback`, while proving retention is fail-closed (no tombstone/ledger success => no deletion).

**Architecture:** Start from 1.7.0 baseline `9e2ed16` in `~/mimir-1.8.0-dev` and adopt the shipped session-end prototype from `github/feat/hooks-session-end` commit `3f93d67` (`learning.session_end`, `/v8/hooks/session-end`, tests). Keep all hook ingestion in the existing DLP + fingerprint + idempotency pipeline and crystallize exactly one STM candidate from the redacted transcript. Add additive store columns/migrations for usage/spacing heat signals derived from `search_feedback`, make `query._decay_factor`/ranking consume those signals (and let evolve/feedback write them), and harden retention so purge/deletion only executes after tombstone+ledger steps succeed. Adapter stubs stay minimal and declarative (A-tier Claude Code/Codex) without changing backend `/api/*` contracts.

**Tech Stack:** Python 3.11+, SQLite (WAL, STRICT/additive migrations), FastAPI (`mimir_v8/api.py`), core services (`mimir_v8/learning.py`, `store.py`, `retention.py`, `evolve.py`, `query.py`), pytest/ruff, git worktree `~/mimir-1.8.0-dev` on n100.

**Spec:** `docs/superpowers/specs/2026-11-12-mimir-1.7-to-2.0-roadmap-design.md` (§5 1.8.0, §5.1–§5.4, §7.5 F1/F2/F5, §8, §10). Prototype references: `github/feat/hooks-session-end` commits `898ce33` and `3f93d67`.

## Global Constraints

- **No auto-write to `facts` from hooks/STM:** SessionStart/SessionEnd/hooks produce stored conversation rows and/or candidate/review artifacts only; facts enter only via existing review/`remember()` paths (spec §5.1, §10). `session_end` must reject `memory_mode="explicit"` (use `remember()`).
- **Fail-closed ingestion and retention:** no LLM => Tier-0 deterministic path only (never store raw/fulltext fallback). No tombstone/ledger write success => no deletion/purge (spec §5.4, F5). DLP redaction runs before candidate crystallization/storage.
- **Idempotency preserved:** hook ingest/replay returns the same source/candidate identity for the same idempotency key; no duplicate candidates or facts on replay.
- **Additive, replayable migrations:** heat counters/timestamps are additive columns/indexes with safe defaults/backfill (legacy rows stay NULL/0; never fabricate usage history) and idempotent application.
- **SQLite correctness:** keep WAL-safe patterns and 1.7.0 `BEGIN IMMEDIATE` lock-retry discipline; no JSON file locks, no external vector DB.
- **Backend/API contract stability:** do not change/remove existing `/api/*` routes or payloads (dashboard v5 is out of scope for 1.8, spec §11/§13 row 7). New hook routes are additive (`/v8/hooks/*`).
- **Evidence-backed verification:** run targeted pytest for touched areas and `ruff` on touched modules; record command output. Treat known Windows `TemporaryDirectory` cleanup `PermissionError` noise as pre-existing only if reproduced and attributable (do not claim clean without evidence).
- **No destructive git:** work on a dedicated 1.8 branch in `~/mimir-1.8.0-dev`; no reset/force-push/rebase of shared branches.

## Review Focus

- **SessionEnd replay/idempotency:** same envelope/idempotency key replay returns identical `run_id/source_id/candidate_id` and does not create a second candidate or any fact row.
- **DLP boundary on hook path:** transcript with secret/PII markers is redacted before candidate content/summary are persisted; raw secret string absent from `candidate_facts` and stored conversation redacted fields.
- **Heat signal consumed, not just stored:** `search_feedback`/derived usage-spacing fields influence `_decay_factor` or final ranking; a fact with repeated useful/attended signals decays/ranks differently than an untouched peer of same age (and legacy NULL/0 rows behave like "no evidence").
- **Migration/backfill safety:** upgrade on an existing DB adds columns/indexes without error, leaves existing rows queryable/retention-safe, and does not invent counts/timestamps.
- **Retention fail-closed proof:** if tombstone or ledger/event write fails during retention execution, the target fact/message content is not purged/deleted (test proves no deletion side effect).

def build_session_end_payload(*, connector_type: str, connector_id: str, session_id: str,
                              owner_principal: str, messages: list[dict], idempotency_key: str,
                              memory_mode: str = "observe", title: str | None = None) -> dict:
