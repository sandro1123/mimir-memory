## 1. 工作协议（每个 PR 都按这个来）

1. 一个任务一个分支：`feat/<task-id>-<slug>` 或 `fix/<task-id>-<slug>`。
2. 一个 PR 只做一个任务；超过 ~400 行 diff 就拆。
3. 行为变更必须带测试（仓库既有纪律：TDD，先红后绿）。
4. 提交信息用约定式：`feat: ...` / `fix: ...` / `docs: ...` / `test: ...`。
5. 合并前 CI 必须全绿；**不要自己合并 PR**，交用户批准。
6. 不推 master、不 force push、不改别人的分支。
7. 碰 schema 的任务必须独占执行（见 §2 的车道约束）。
8. 任何「顺手清理」都不做：不动无关格式、不重排 import、不删既有注释。

## 4. 阶段 A：1.8.0（SCHEMA 22）

> 主题：**自动捕获只产候选，不写事实；热量只有一个所有者。**

### A1 · STM 短时会话层 `session_episode`
- **目标**：会话结束时的内容先进短时层（TTL 24h），可被 `proactive_wake` 会话内注入，
  **不直写 facts**；会话期结束自动结晶为**候选**（沿用 #51 已有的 SessionEnd 路径）。
- **触点**：`mimir_v8/store.py`（新表 + 守卫式建表，照 `crystallize.py` 的 additive-DDL 先例）、
  `mimir_v8/schema.py`（版本 22）、`mimir_v8/migration.py`（迁移段 + 白名单）、
  `mimir_v8/learning.py`、`mimir_v8/relevance.py`（会话内注入读 STM）。
- **表设计要点**：`session_episode(episode_id, session_id, principal, content, redacted, expires_at, crystallized_candidate_id, created_at)`；
  `expires_at` 索引；过期即不可读，**不是**删除。
- **测试**（`tests/test_p34_session_episode.py`）：
  1. 结晶后 `fact` 数量为 0、候选 +1；
  2. TTL 过期后召回不可见，但行仍在（忘 ≠ 删）；
  3. 同会话重复结晶幂等（同 `candidate_id`）；
  4. 跨 principal 不可见（沿用 `can_access` 判定）；
  5. 反向注入：结晶路径抛错 → 事实数仍为 0，候选不残留半条。
- **验收**：CI 绿 + `MIGRATABLE_TARGET_VERSIONS` 含 22 + README/health 的 schema 徽标同步。
- **禁止**：STM 不得成为第五个真相源；不做「STM 过期即删表行」的清理作业。

### A2 · 热量单一所有者（修正 roadmap §5.3 的双重计数）
- **现状事实**：`search_feedback` 不是「只写不读」——`evolve.py:134-161` 按 fact 聚合
  useful/useless，超过 `MIN_SIGNALS_PER_FACT` 后按 ±`CONFIDENCE_DELTA` 调
  `confidence_score`，并写 `fact.evolved` 事件。
- **目标**：显式反馈（用户点「有用/没用」）与隐式使用（召回后确实被 Agent 引用/attend）
  **分成两条信号**，且**只有一条进入排序热量**。
- **触点**：`mimir_v8/schema.py`（新表 `fact_usage`：fact_id / kind=implicit|explicit /
  signal / at）、`mimir_v8/query.py`（`_decay_factor` 旁新增 `_heat_factor`，**默认关闭**）、
  `mimir_v8/evolve.py`（显式反馈保持不变，不再兼管热量）。
- **配置**：`MIMIR_HEAT_SIGNAL=off|shadow|on`。默认 `off`；`shadow` 只记录不排序，用于实测。
- **测试**（`tests/test_p34_heat_single_owner.py`）：
  1. `off` 下排序结果与今日逐条相同（字节级对比同一查询）；
  2. `shadow` 下写入 `fact_usage` 但排序不变；
  3. `on` 下同一 fact 的显式+隐式信号**只被计入一次**（钉死双重计数回归）；
  4. `on` 后 `confidence_score` 不被隐式信号改动。
- **验收**：三种模式各有钉；没有实测报告不许翻默认值（交给 B1）。
- **禁止**：不许在 `search()` 里同步写库（写库必须在事件路径外异步/批量）。

### A3 · Adapter Contract v1 + 单个 harness 安装器
- **目标**：让 1.8 的钩子有「第一个真实客户」，避免 1.9 回头重构 1.8 的硬编码。

- **测试**（`tests/test_p34_adapter_contract.py`）：

  2. 侧表 `fact_bitemporal(fact_id, valid_from, valid_to, tx_time)`，只写新事实。
  3. 重建表 → **否决**（等于放弃不可变哈希链）。
- **触点**：`mimir_v8/schema.py`、`mimir_v8/store.py`、`mimir_v8/query.py`、`mimir_v8/api.py`。
- **测试**：`as_of` 在三点（早于创建 / 创建与取代之间 / 取代之后）返回三组不同结果；
  同一 fact 的 `valid_time` 与 `tx_time` 可分离（先记事实、后补生效时间的场景）。

### E2 · `as_of` 下的诚实判语
- **规则**：`as_of` 时点系统还不知道某事实 → `not_yet_known`；从未存在 → `never_existed`。
  **不允许**把前者报成 `not_found`。
- **测试**：`tests/test_p0a_recall_verdict.py` 扩三态；金标里加一条「只在未来存在」的样本。
- **验收**：G1 的 `hit@5 ≥ 0.875` 回放报告入 `docs/RESULTS.md`。

### E3 · 安全门（走私有披露，不写公开 issue）
> 三条都是我在 2026-11-16 静态审计中确认的 HIGH；细节不在公开文档里展开，
> 实施者读本节联系维护者拿私有说明，或自行复现后按 `SECURITY.md` 流程处理。

1. **联邦收件人隔离**：现协议是「每个节点持一把对称 Fernet 密钥，注册时把密钥本身
   当公钥交给 peer」。后果：发给 B 的信封，同级的 C 也持有 A 的密钥因而可解。
   修法方向：改为 per-recipient 密钥（X25519 协商或每对节点独立密钥 + envelope 里带
   recipient 标识），保留 `federation_grants` 的授权语义；旧信封做一段只读兼容窗口。
2. **逐事件签名**：事件体里的 `node_id` 只是与 peer 注册表比对，没有密码学绑定，
   已注册 peer 可冒用他节点身份。修法：对 `(crdt_key, lamport, node_id, op, value)`
   做 Ed25519 签名，ingest 端验签，未签名/验签失败一律拒收（fail-closed）。
3. **Vault 写入路径**：`vault_publish.py:70,88-89` 直接 `vault_root / rel_path` 后
   `mkdir` + `write_text`，未拒绝符号链接与解析后越界。修法：`Path.resolve()` 后断言
   在 `vault_root` 内、目标及任意父级不是 symlink、写临时文件后原子替换。
- **测试**（三条都要反向注入必红）：`tests/test_p20_security_red_team.py`
  ① 同级 peer 解 B 的信封必失败；② 篡改字段/伪造签名/无签名必拒收；
  ③ 符号链接目标必拒写且不留残留。
- **发布纪律**：三条全绿 + `SECURITY.md` 补披露记录之前，**不得对外发布仓库或打 2.0 tag**。

### E4 · 谱系归一（`fact_supersessions` 唯一真相）
